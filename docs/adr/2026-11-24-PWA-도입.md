# PWA 도입

## 상태

제안

## 맥락

웹 배포본을 태블릿 홈 화면에 앱처럼 설치해 쓰고 싶다. 지금은 manifest와 서비스 워커가 없어 브라우저가 설치를 권하지 않는다. 네트워크가 잠깐 끊긴 채 새로 고치면 흰 화면이 된다.

## 결정

- manifest와 서비스 워커를 직접 써서 넣는다. vite-plugin-pwa는 쓰지 않는다. 캐시 규칙이 세 줄이라 의존성을 늘릴 이유가 없었다.
- 서비스 워커는 웹 배포본에서만 등록한다. 개발 서버와 네이티브 빌드(`--mode native`), Capacitor 실행 환경에서는 등록하지 않는다.
- 캐시 규칙
  - 화면 이동은 네트워크 먼저. 실패하면 캐시된 index.html을 준다. 배포 직후에도 새 index.html을 받으므로 stale-chunk-reload와 겹치지 않는다.
  - `/assets/` 해시 파일은 캐시 먼저. 200개를 넘으면 오래된 것부터 지운다.
  - `/api/`와 다른 출처(Supabase 삽화와 음성, 로그인 SDK)는 건드리지 않는다.
- 화면 조각을 미리 다 받아 두지는 않는다. 한 번 열어 본 화면만 오프라인에서 다시 뜬다. 동화 진행은 어차피 API가 있어야 한다.

## 작업 내용

- `public/manifest.webmanifest` 추가. 이름 큐스토리, standalone, 시작 주소와 범위 `/`, 배경과 테마 색 `#FAF8FC`.
- `public/brand/qstory-icon-512.png`, `qstory-icon-maskable-512.png` 추가. 앞의 것은 `qstory-mark.svg`를, 뒤의 것은 `assets/logo.png`를 512로 그렸다.
- `public/sw.js` 추가. 캐시 이름은 `qstory-shell-v1`, `qstory-assets-v1`. 규칙을 바꾸면 `CACHE_VERSION`을 올린다.
- `src/app/register-service-worker.ts`와 테스트 추가. `src/app/main.tsx`에서 부른다.
- `index.html`에 manifest 링크와 iOS 홈 화면용 메타 추가.
- `vercel.json`에 `/sw.js` `Cache-Control: no-cache`, `/manifest.webmanifest` Content-Type 추가. CSP에는 `worker-src 'self'`, `manifest-src 'self'`가 이미 있어 고치지 않았다.
- `container-server.mjs`에 `.webmanifest` Content-Type 추가. `sw.js`는 기존 규칙대로 `max-age=0, must-revalidate`로 나간다.

## 확인 방법

- `npm run typecheck`, `npm run lint`(오류 0), `npm test`(509개 통과), `npx vite build`.
- 빌드 결과물을 `container-server.mjs`로 띄우고 헤드리스 Edge로 확인했다.
  - manifest 파싱 오류 없음. 아이콘 세 장이 선언한 크기와 같다.
  - 서비스 워커가 `/` 범위로 등록되고 페이지를 제어한다.
  - `/api/` 응답은 캐시에 들어가지 않는다.
  - 오프라인으로 바꾸고 새로 고쳐도 첫 화면이 그대로 뜬다.
  - 오프라인에서 한 번도 안 연 `/login`으로 가면 화면 조각이 없어 빈 화면이다. 위 결정대로다.
- `vite build --mode native` 결과물에는 `sw.js` 등록 코드가 없다.
- 실제 기기 설치(갤럭시탭 크롬, 아이패드 사파리)와 dev.qstory.ai.kr 배포본 확인은 아직 하지 않았다.

## 영향

- 되돌릴 때는 등록 코드만 빼면 안 된다. 이미 설치된 서비스 워커가 남는다. `sw.js`를 캐시를 지우고 스스로 등록 해제하는 내용으로 바꿔 한 번 배포해야 한다.
- 남은 일: 오프라인에서 안 열어 본 화면으로 갈 때 안내 화면, 새 버전 알림.
