# PWA 설치 안내 배너

## 상태

제안

## 맥락

PWA를 넣었지만(2026-11-24-PWA-도입.md) 사용자가 브라우저 메뉴에서 직접 "앱 설치"나 "홈 화면에 추가"를 찾아야 한다. 대부분은 그런 메뉴가 있는지 모른다. 화면에서 먼저 권하고 싶다.

## 결정

- 화면 아래에 작은 카드로 설치를 권한다.
- 크롬 계열(갤럭시탭)은 브라우저가 주는 `beforeinstallprompt` 이벤트를 잡아 둔다. "설치"를 누르면 브라우저 설치 창이 뜬다.
- iOS 사파리는 설치 창을 띄우는 API가 없다. "공유 버튼을 누르고 홈 화면에 추가"라는 안내만 보여 준다. iOS의 크롬이나 카카오톡 안 브라우저는 메뉴 위치가 달라 대상에서 뺐다.
- 띄우지 않는 경우
  - 이미 홈 화면에서 앱으로 열었을 때, 네이티브 앱일 때
  - 닫은 뒤 2주 동안. 브라우저 설치 창에서 취소한 것도 닫은 것으로 친다.
  - 첫 화면, 로그인·가입·온보딩·결제·초대 화면. 아래쪽 버튼을 가린다.
  - 동화를 읽는 화면(`/demo`, `/stories/:id/play`)과 팀 내부 화면

## 작업 내용

- `src/features/pwa-install/` 추가
  - `model/install-prompt-logic.ts`와 테스트: 언제 무엇을 띄울지 정하는 순수 함수
  - `model/deferred-install-prompt.ts`: `beforeinstallprompt`, `appinstalled` 이벤트 보관
  - `ui/pwa-install-prompt.tsx`: 배너
- `src/app/main.tsx`에서 이벤트를 먼저 듣기 시작한다. 이벤트가 화면을 그리기 전에 올 수 있어서다.
- `src/app/App.tsx` 라우터 안에 `PwaInstallPrompt`를 한 번 넣었다.
- 닫은 시각은 localStorage `qstory.pwaInstallDismissedAt`에 둔다.

## 확인 방법

- `npm run typecheck`, `npm run lint`(오류 0), `npm test`(517개 통과), `npx vite build`.
- 빌드 결과물을 `container-server.mjs`로 띄우고 헤드리스 Edge로 확인했다.
  - `beforeinstallprompt`를 쏘면 배너가 뜨고 브라우저 기본 안내는 막힌다.
  - "설치"를 누르면 `prompt()`가 한 번 불린다. 취소하면 배너가 사라지고 새로 고쳐도 다시 뜨지 않는다.
  - 첫 화면과 `/demo`에서는 뜨지 않는다.
  - 아이패드 사파리 UA에서는 안내 문구가 뜨고 "확인"을 누르면 사라진다.
- 실제 갤럭시탭 크롬과 아이패드 사파리에서는 아직 보지 않았다.

## 영향

- 되돌릴 때는 `App.tsx`의 `PwaInstallPrompt`와 `main.tsx`의 `installDeferredPromptCapture()`를 빼면 된다. 그러면 크롬 기본 안내로 돌아간다.
- 남은 일: 설치 수락과 닫기 횟수 기록, 2주 간격이 맞는지 판단.
