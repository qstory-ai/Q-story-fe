# 새 동화 한 편 만들기 - 기획에서 리포트까지

「헨젤과 그레텔」(HG) 한 편을 만든 순서를 그대로 적은 위키다. 두 번째 동화부터는 이 순서대로 하면 된다.
맨 아래에 **동화 한 편 만드는 비용**과 **한 번 읽을 때 드는 비용** 추정이 있다.

마지막 갱신: 2026-10-21 · 기준 저장소: `Q-story-fe` `content/`, `Q-story-be` `storyadmin/`

---

## 0. 한눈에 보기

| 단계 | 하는 사람 | 들어오는 것 | 나가는 것 | 도구 |
| --- | --- | --- | --- | --- |
| 1 기획 | PM | 원작·대상 연령 | 대본 10화, 질문 초대 3곳, 인물 설정, 삽화 목록 | 노션 |
| 2 콘텐츠 파일 | 개발 | 1의 산출물 | `content/stories/<slug>/` 12개 파일 | 에디터, `npm run content:*` |

## 1. 기획에서 넘겨야 하는 것 (PM → 개발)

노션 한 페이지에 아래가 다 있으면 개발이 바로 2단계로 옮길 수 있다.

1. **기본 정보**: 제목, storyId(두 글자, 예 `HG`), slug(예 `hansel-gretel`), 대상 연령, 원작 출처.
2. **대본 10화**: 화마다 제목, 문장 단위로 화자(내레이터/인물)와 글. 한 화는 보통 3~6장면(그림). 문장마다 "이 문장을 들을 때 보이는 그림"을 표시한다.
3. **질문 초대 3곳(A/B/C)**: 어느 화 어느 문장 뒤에 멈추는지, 그때의 상황 한 줄, 아이에게 거는 첫 말, **준비된 행동 2개**(이름, 뜻 한 줄, 그레텔이 받아 말하는 확인 문장, 리포트에 적을 요약 한 줄, 전개 대본 3~6줄, 전개 그림 설명), **도움 단계 3~4줄**(정답을 먼저 주지 않는 순서), 마지막 단계에서만 보여 줄 예시 선택지 2개, **시도 장면 막힘 후보 3개**(아이가 준비 안 된 방법을 말했을 때 "해 보고 안 됐다"로 보여 줄 그림 설명).
4. **인물 설정(페르소나)**: 인물마다 나이대, 성격 3단어, 한 줄 소개, 말끝·말버릇, 허용 감정과 상한, 외형 사실, 관계, **아는 것/모르는 것/먼저 말하지 않는 것**. 말버릇에 "오빠, 저기 봐"처럼 상대 호칭을 넣지 않는다(10/21 QA: 아이를 오빠라고 부름).
5. **목소리 캐스팅**: 인물별 목소리 이름(Gemini 프리셋), 연출 한 줄(영어), 같은 인물이 변하는 경우(할머니→마녀) 표시.
6. **안전·금지 지식**: 질문 초대마다 말하면 안 되는 것(폭력 묘사, 결말 선공개, 준비 안 된 출구 등).
7. **토론 질문**: 완주 뒤 보호자가 쓸 질문 3묶음(진술, 연령별 힌트).
8. **리포트 문구**: 질문 초대별 주제·초점·장면 제목·대표 그림·후속 질문, 질문 안 한 아이용 기본 문구, 3분 활동.
9. **삽화 목록**: 그림마다 slug, 장소, 시간대, 등장인물, 들어가는 행동, 시작 상태→끝 상태.

## 2. 코드와 Supabase에 넣는 것

### 2-1. 파일 (Q-story-fe `content/stories/<slug>/`)

| 파일 | 담는 것 | 1단계의 어디서 오나 |
| --- | --- | --- |
| `script.qstory` | 10화 대본. `[SCENE | id | title=]`, `[VISUAL | id | asset= | mode=]`, `[NARRATOR]`/`[GRETEL | DIALOGUE]` 블록, 질문 초대 앵커 | 2, 3 |
| `fallbacks.qstory` | 준비된 행동 전개 대본(`[FALLBACK | familyId]` + `[VISUAL]` + 대사, `[SYSTEM | REJOIN:C | target=]`로 본편 복귀 지점) | 3 |
| `story.yaml` | 제목, 장면 순서, `inviteHelp`(도움 단계·예시 선택지), `attemptBackdrops`(막힘 그림 후보) | 3 |
| `route-context.yaml` | 질문 초대별 `situation`, `forbiddenKnowledge`, `actionFamilies`(id, meaning, acknowledgementText, reportSummary, bridgeAudioId, branchAssetId, choiceCopyVariants), `routePromptVersion` | 3, 6 |
| `personas.yaml` | 인물 페르소나 시트 - 그대로 그레텔 대화 프롬프트가 된다 | 4 |
| `cast.yaml` | 목소리 캐스팅(voice, direction, profile), castVersion | 5 |
| `discussion-bank.yaml` | 토론 질문 | 7 |
| `report-copy.yaml` | 리포트 문구, 행동 → 역량 이름(`C_DISTRACT_AND_TAKE_KEYS: 함께 움직일 방법 정하기`) | 8 |
| `assets.json` | 그림·소리 목록(slug, category SCENE_ART/BRANCH_ART/NARRATION/BRIDGE, file, integrity) | 3단계·4단계 결과 |
| `visual-provenance.yaml` | 그림마다 프롬프트·모델·inputHash·승인자 | 3단계 결과 |
| `qa-contract.yaml` | 자동 검사 기준: 소리(길이·음량·무음 비율), 행동 전개마다 꼭 나와야 할 말/나오면 안 되는 말 | 3, 6 |
| `release.yaml` | availability(BETA/PUBLIC)와 승인 체크(automated/editorial/safety/visual/audio/device) | 7단계 |
| `evaluation.jsonl` | 라우팅 평가 fixture 연결 | 5단계 |

그리고 `content/registry.yaml`의 `stories:`에 `{ storyId, slug, availability }` 한 줄을 더한다. 라우팅 프롬프트(`content/prompts/*.yaml`)는 동화끼리 공유하고 `route-context.yaml`에서 버전을 가리킨다.

### 2-2. 명령 순서

```bash
npm run content:generate   # yaml/qstory → generated/story-package.generated.json, generated-story-content.json, story-assets.generated.ts
npm run content:check      # 대본·자산·qa-contract 자동 검사(그림 빠짐, 소리 길이, 금지어 등)
npm run assets:upload      # assets/story/<slug>/ 그림·소리 → Supabase Storage (<slug>/illustrations/*.webp, <slug>/audio/*.mp3)
npm run content:import     # generated 두 파일 → BE POST /v1/admin/stories/import (X-Admin-Token)
```

- 앱 번들에는 그림·소리를 싣지 않는다. Storage 공개 URL을 FE(`story-assets.generated.ts`)와 BE(`StoryAssetUrls`)가 같은 규칙으로 만든다.
- 소리 원본은 저장소에 두지 않고 버킷이 유일한 사본이다(HG 기준 `hansel-gretel/audio/` 545개 33.7MB, 그중 현재 대본이 쓰는 건 175개).

### 2-3. 임포트가 쓰는 BE 테이블 (Supabase Postgres)

`StoryImportService`가 한 번에 바꿔 넣는다: `story`, `story_revision`, `story_scene`, `story_segment`, `story_anchor`, `story_action_family`, `story_fallback_segment`, `story_persona`, `story_cast`, `story_asset`, `story_visual_reference_pack`, `route_prompt`, `route_prompt_stage`.
어드민 API(`/v1/admin/stories/...`)로 장면·문장 수정, 수정 이력 되돌리기, 바뀐 문장의 내레이션 재생성(`/segments/{id}/narration/rerender`, `/narration/stale`)을 할 수 있다.

## 3. 삽화 제작 (스타일 01 · Higgsfield)

1. **캐릭터 시트** - 디자이너가 피그마 「삽화」 파일에 인물마다 3면도 1장(현재 5명: 그레텔·헨젤·아버지·새어머니·할머니/마녀). 개발은 Figma MCP로 받아 `docs/삽화/style-01-refs/`에 `gretel-sheet.png` 같은 이름으로 둔다. 배경 분위기 참고 1~2장은 `background-1.png`, `background-2.png`.
2. **프롬프트** - 노션 "삽화 제작 방법"의 공통 프롬프트(고정)를 `scripts/illustrations/style-01.mjs`에 같은 내용으로 둔다(API 상한 5,000자라 줄인 판). 장면 칸(STORY·COMPOSITION·BACKGROUND·LIGHTING)은 `npm run art:jobs`가 대본에서 자동으로 채운다. 구도 규칙: 앱이 그림 아래 40%를 자막·대화창으로 덮으므로 얼굴·손은 위~가운데.
3. **생성** - `npm run art:generate -- --refs <시트 폴더>` (모델 GPT Image 2.5 Flare, 16:9, 기본 **후보 1장·2K·high**, 장당 약 $0.275). 인물이 나오는 장면엔 그 인물 시트가 자동으로 붙는다. 끊기면 같은 명령을 다시 - 받은 후보는 건너뛴다. 마음에 안 드는 장면만 `--only <장면> --variants 2`로 하나 더 만든다. 후보 수나 해상도를 올리기 전엔 장수와 금액을 먼저 말하고 확인받는다(HG 10/21: 5달러 충전에 후보 2장·4K 시험을 돌려 모자랐음).
4. **고르기** - `npm run art:review` → `review.html`에서 지금 그림과 후보 비교, `picks.json`에 번호. 품질 기준은 노션 QA 문서 "1. 삽화".
5. **넣기** - `npm run art:promote`(1920×1080 WebP, `assets.json`·`visual-provenance.yaml` 갱신) → `content:generate` → `assets:upload --kind images` → `content:import`.

수정 요령(디자이너 문서): 얼굴·복장만 다르면 Sunburst로 부분 수정, 구도가 다르면 프롬프트 고쳐 재생성, 배경이 사실적이면 질감 지시 보강, 반복해서 틀어지면 시트·모델 설정 재확인.

### 3-1. 실시간 삽화 (앱 안에서 만드는 그림)

정적 삽화 50장 말고 두 가지 그림은 아이가 말한 내용대로 **앱이 실시간으로** 만든다. 둘 다 같은 Higgsfield 모델·같은 공통 프롬프트·같은 인물 시트를 써서 정적 그림과 섞여도 티가 안 나게 했다.

| 그림 | 언제 | 어떻게 보이나 |
| --- | --- | --- |
| 새 선택지 전개 그림 | 질문 지점에서 아이 질문이 준비된 행동 어디에도 안 맞아 새 선택지 3개를 만들 때(`route-context.yaml`의 `liveBranchGeneration: true`인 지점만) | 선택지 3개와 전개 대본·그림이 이야기 콘텐츠에 추가되고, 아이가 고른 뒤 전개 그림으로 나온다 |
| 시도 장면 막힘 그림 | 그레텔 대화에서 준비 안 된 방법을 "가서 → 해 보고 → 막힘"으로 보여 줄 때 | 처음엔 미리 만든 막힘 그림 6장 중 하나가 뜨고, 20~50초 뒤 실시간 그림이 다 되면 그 그림으로 바뀐다(시도 장면이 끝났으면 안 바꾼다) |

- 상한: 질문 지점 하나·읽기 세션 하나에 **3장까지**(새 선택지 + 시도 장면 합계, 장당 2k·high ≈ $0.275 → 질문 지점당 1달러 안쪽). 백엔드 `QSTORY_REALTIME_IMAGE_MAX_PER_ANCHOR_SESSION`로 바꾼다. 상한에 닿으면 새 선택지는 기존 행동으로 채우고, 시도 장면은 미리 만든 그림만 쓴다.
- 새 동화에서 할 일: 인물 시트를 버킷 `<slug>/references/<인물>-sheet.png`로 올리고(`scripts/illustrations/README.md` 0-1), `visual-generation-contract.ts`의 인물 외형 사실을 시트와 맞춘다(실시간 프롬프트에 글로 들어간다). 할머니=마녀처럼 같은 사람은 시트 하나를 두 라벨이 쓴다(백엔드 `RealtimeImageService.SHEET_FILES`).
- 키: Railway `HIGGSFIELD_API_KEY_ID`/`HIGGSFIELD_API_KEY_SECRET`. 비어 있으면 새 선택지는 OpenRouter 이미지 모델(그림체 다름)로, 시도 장면은 미리 만든 그림으로 간다.

## 4. 목소리 (내레이션)

- `cast.yaml`에 인물별 Gemini 프리셋 목소리와 연출을 적는다(HG: 내레이터 Sulafat, 아버지 Charon, 새어머니 Kore, 헨젤 Fenrir, 그레텔 Leda, 할머니/마녀 Gacrux - 같은 목소리에 연출만 다르게).
- 내레이션은 BE가 Gemini TTS(Interactions API, `gemini-3.1-flash-tts-preview`)로 만들어 mp3로 저장하고 -17 LUFS로 음량을 맞춘다. 문장을 고치면 `/narration/stale`로 어긋난 줄을 찾고 `/narration/rerender`로 그 줄만 다시 만든다.
- 실시간으로 만드는 소리는 따로 있다: 그레텔 답, 시도 장면 3줄, 새로 만든 선택지 읽기. 같은 목소리·같은 음량 규칙이라 녹음 소리와 섞여도 튀지 않게 했지만 완전히 같지는 않다(QA 항목 "녹음 음성과 실시간 음성의 차이").
- 검사: `qa-contract.yaml`의 소리 기준(최소 0.35초, RMS -42dB 이상, 무음 45% 이하 등)을 `content:check`가 본다.

## 5. 캐릭터 대화 · 질문 초대 설계

**질문 초대 한 곳의 구성 요소**

| 요소 | 어디에 | 하는 일 |
| --- | --- | --- |
| 상황(situation) | route-context | 지금 장면에서 무엇이 문제인지 한 줄 - 그레텔이 되돌아오는 기준점 |
| 준비된 행동 2개(actionFamilies) | route-context + fallbacks.qstory | 아이 말이 이 뜻과 같으면 확인 뒤 전개 대본·그림으로 이어진다 |
| 도움 단계(inviteHelp.steps) | story.yaml | "도와줘"마다 한 단계씩. 단서 → 생각할 거리 → 예시. 마지막에만 선택지 2개 |
| 시도 장면(attemptBackdrops) | story.yaml | 준비 안 된 방법은 "가서 → 해 보고 → 막힘" 3줄로 보여 주고 원래 질문으로 돌아온다 |
| 금지 지식(forbiddenKnowledge) | route-context | 프롬프트에 그대로 들어가는 안전·스포일러 규칙 |
| 페르소나 | personas.yaml | 그레텔 말투·아는 것/모르는 것. 임포트되면 `story_persona`에서 프롬프트로 조립 |

**동작 방식(BE)**
- 그레텔 대화: `OpenRouterClient.companionSystemPrompt`(GRETEL_DIALOGUE_V2_2, 시도 장면 V9) + 페르소나 + 지금 장면·앞 대화 → Gemini 3.6 Flash(OpenRouter). 답은 1~3문장, 되묻기는 두 번에 한 번, 준비된 행동과 뜻이 같으면 `proposedActionFamilyId`로 확인 카드.
- 질문 라우팅(녹음 올리는 방식): 안전 게이트 → 분류(classifyRoute) → 필요하면 답/선택지 생성. 프롬프트는 `content/prompts/qstory-route-prompt-v7-coverage.yaml`.
- 받아 적기(STT): 실시간은 RTZR 스트리밍(`/v1/stt/stream`), 끊기면 녹음 전체 올리기로 자동 전환.
- 대화 원장: 아이 발화 원문과 답을 `conversation_record`에 1년 보관(열람 API 없음, 연락처 마스킹).

**새 동화에서 꼭 확인할 것**

## 6. 리포트

- `report-copy.yaml`: 완주 문장, 질문 초대별 주제·초점·대표 그림·후속 질문, 질문을 안 한 아이용 기본 주제, 3분 활동, 행동 → 역량 이름.
- 완주 시 `story_completion`(세션 id로 중복 방지, 반·기관 스냅샷) + 대화 태그(`companion_chat_turn`, 90일) + 선택한 행동이 리포트의 재료다. 분석 문장은 `reportanalysis`가 만든다.
- 보호자·선생님 화면은 공통 위젯(`widgets/session-report`)이라 새 동화는 문구 파일만 채우면 된다. 아이를 비교·낙인찍는 문장이 없는지 QA 문서 "6. 리포트"로 본다.
